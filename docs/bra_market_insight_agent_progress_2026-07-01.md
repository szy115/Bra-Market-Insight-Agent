# Bra-Market-Insight-Agent 思路及进度

日期：2026-07-01  
项目：Bra-Market-Insight-Agent / Hsia R&D Insight Agent MVP  
当前定位：Reddit-first 市场洞察 Agent MVP，正在扩展到 Amazon、媒体/榜单文章和竞品信息卡片

## 1. 当前项目定位

现在这个项目可以理解成一个面向美国文胸细分类目的市场洞察与研发情报 MVP。

它的核心闭环是：

输入一个文胸细分类目 → 自动抓取外部公开数据 → 结构化分析 → 调 LLM 做证据驱动总结 → 在 Web UI 中展示报告、数据量审计和证据链。

第一阶段不是完整 PLM，也不是直接替代设计师或商品企划，而是先把人工市场调研、竞品整理和研发情报归纳的效率提上来。

更准确地说，当前系统仍然是 workflow + tool-use 形态，还不是复杂 multi-agent。它已经具备多数据源采集、结构化分析、LLM 总结和可视化报告能力，但还没有真正的自主任务规划、状态编排和多轮自我补数能力。

## 2. 上午完成的 Reddit-first 市场洞察闭环

上午的主线是把 Reddit-first 的市场洞察 MVP 跑通。

当前流程：

1. 用户在 Research 页输入细分类目，例如 `wireless bras for large bust`。
2. 系统扩展 Reddit 搜索 query。
3. 根据 Settings 读取抓取配置：
   - 抓多少帖子；
   - 多少帖子拉评论；
   - 每帖多少评论；
   - 多少帖子和评论样本喂给 AI。
4. 数据源优先走 Agent Reach + OpenCLI：
   - 复用 Chrome Reddit 登录态；
   - Reddit search 抓帖子；
   - Reddit read 抓帖子详情和评论。
5. 后端把帖子、评论标准化成统一 Evidence 数据结构。
6. 做基础分析：
   - 实际帖子数；
   - 实际评论数；
   - subreddit 覆盖；
   - 趋势；
   - 情绪；
   - 痛点主题；
   - 品牌/尺码提及；
   - 机会假设。
7. 把压缩后的证据上下文喂给 LLM：
   - 不把全部原始数据直接塞给 AI；
   - 控制 AI 看到多少帖子、多少评论样本；
   - 要求 AI 只基于 Reddit 证据输出。
8. 页面展示报告，并新增数据量审计：
   - 请求多少帖子；
   - 实际拿到多少帖子；
   - 实际拿到多少评论正文；
   - 实际喂给 AI 多少帖子和评论样本。

这一阶段已经跑通 MVP 最重要的闭环：数据获取、证据链、估算逻辑、AI 总结、UI 展示。

## 3. 下午新增能力

下午的工作把项目从 Reddit-only 拓展到了更接近“美国大胸显小市场与爆款基因 Agent”的形态。

### 3.1 Amazon 商品信息采集

新增了 Amazon 商品侧的数据采集与分析能力。

当前能力：

- 支持 Research 页选择 Amazon 商品源；
- 输入文胸细分类目后，系统会做 Amazon 关键词扩展；
- 通过 Amazon/OpenCLI provider 抓取商品搜索结果和商品相关信息；
- 结构化提取：
  - 商品标题；
  - 品牌；
  - ASIN；
  - 价格；
  - 评分；
  - review 数；
  - badge；
  - sponsored 状态；
  - bullet points；
  - review/discussion 样本。

报告中新增 Amazon 数据量审计：

- 扩展了多少关键词；
- 每个关键词请求多少商品；
- 实际采集多少商品；
- 去重后多少商品；
- 采集到多少 review 样本；
- 实际喂给 AI 多少商品和 review 样本。

这一步让系统不再只看用户讨论，也能看到货架上的竞品、价格带、评分和 review 信号。

### 3.2 综合洞察

新增了 Reddit + Amazon 的综合洞察能力。

当前能力：

- 支持 Research 页选择“综合洞察”；
- 如果当前缺少 Reddit 或 Amazon 数据，系统会自动补抓缺失的数据源；
- 后端构建 Reddit + Amazon 的统一 evidence pool；
- LLM 基于证据池输出综合判断；
- 如果 LLM 不可用，系统会使用保守的本地规则生成 fallback 综合洞察。

综合洞察报告包含：

- 一句话结论；
- 机会；
- 风险；
- 研发建议；
- 品牌沟通建议；
- 证据链；
- 数据缺口。

关键点是：综合洞察不是凭空总结，而是每条判断都保留可点击的 Reddit 或 Amazon 来源引用。

### 3.3 美国媒体测评文章与公开榜单文章抓取

新增了媒体/榜单文章入口。

当前能力：

- Research 页新增 `媒体/榜单文章` 数据源；
- 用户可以粘贴美国媒体测评、公开榜单、公开报告链接；
- 后端通过 Agent Reach web 路由/Jina Reader 读取公开网页正文；
- 每篇文章生成结构化卡片。

文章卡片包含：

- 标题；
- URL；
- 域名；
- 来源类型；
- 权威评分；
- 权威等级；
- 权威依据；
- 注意事项；
- 品牌提及；
- 产品/结构信号；
- 证据摘录；
- 可读正文长度。

当前来源类型包括：

- 媒体文章；
- 媒体测评；
- 公开榜单；
- 行业研究报告。

权威可靠性不是靠 AI 直接保证，而是通过来源审计做提示。系统会检查：

- 是否来自已知美国媒体/测评站点；
- 是否像公开榜单或测评文章；
- 是否包含作者/日期；
- 是否包含 tested、reviewed、expert、lab 等测试语境；
- 是否提到多个已知品牌；
- 正文是否足够长；
- 是否出现 affiliate、commission、sponsored 等商业榜单提示。

专业行业研究报告的边界：

- 可读取公开报告页、免费摘要、公开 PDF，或用户有授权并提供的链接/文件；
- 不绕过付费墙；
- 当前更适合做方向判断和市场背景，不替代购买完整行业数据源。

### 3.4 竞品发现与竞品监控入口

新增了左侧一级导航 `竞品`，与 `研究`、`设置` 平级。

竞品页目前分为两个细分入口：

- 竞品发现；
- 竞品监控。

第一版优先把“竞品发现”跑通，数据源先用 Amazon。

原因：

- Amazon 商品页有更结构化的商品、价格、评分、review、badge 信号；
- 比 Reddit 更适合自动生成候选竞品；
- Reddit 更适合作为后续验证品牌提及、用户痛点语言和真实使用场景的补充来源。

竞品发现当前能力：

- 输入关键词，例如 `minimizer bra`；
- 设置每关键词商品数；
- 设置候选数；
- 从 Amazon 抓取商品；
- 对商品做 Hsia relevance 评分；
- 生成候选竞品池。

候选评分会参考：

- 是否匹配 minimizer/full coverage/large bust/support/smoothing 等语言；
- 是否落在 Hsia 目标价格带或升级款测试价格带；
- 评分；
- review 数；
- Amazon badge；
- 是否 sponsored；
- review 样本质量；
- 是否在多个扩展关键词中出现。

每个候选竞品卡片包含：

- 平台；
- 品牌；
- 商品标题；
- 价格；
- 评分/review 数；
- ASIN；
- badge；
- 匹配关键词；
- 优先级；
- 为什么值得盯；
- 风险；
- 卖点证据；
- review 证据。

交互上：

- 竞品发现页只保留发现输入区；
- 点击“发现竞品”后，会自动跳到竞品监控页；
- 竞品监控页不再展示发现搜索栏；
- 监控页展示候选池，为后续 active/watchlist/rejected/archive 状态管理预留空间。

当前的“竞品监控”还不是持续自动监控系统，更准确地说是候选竞品池和监控卡片入口。下一步需要补齐竞品状态、变化追踪、周期性重跑和人工反馈。

### 3.5 历史研究

新增并调整了历史研究入口。

当前能力：

- Research 页右上角有 `保存当前研究`；
- Research 页右上角有 `历史研究`；
- 点击后进入历史研究视图；
- 左侧是一条条保存过的研究记录；
- 点击某条记录后，右侧展开完整研究结果。

历史详情现在通过按钮切换不同报告页，而不是把所有报告堆在同一页：

- 综合洞察；
- Reddit；
- Amazon；
- 媒体/榜单文章。

如果某条历史记录没有某类报告，对应按钮不会出现。

历史详情中还保留 `载入到研究页`，用于把某条历史研究恢复成当前研究状态继续分析。

## 5. 当前还不是完整 Agent 的地方

当前系统仍然缺少真正的状态编排和自主任务规划能力。

它现在不会自动判断：

- 当前数据不够时，要不要自动换 query；
- 哪些 subreddit 数据质量更高；
- 是否应该补抓更多评论；
- 是否应该二次检索竞品、价格、Amazon 评论；
- 是否应该自动补抓媒体榜单；
- 是否应该把一次研究拆成多个子任务；
- 哪些候选竞品应该进入 active/watchlist/rejected；
- 下一轮研究是否应该优先验证某个风险或机会；
- 人工反馈如何改变下一轮优先级。

因此当前更准确的名称是：

带 LLM 分析能力的多数据源采集与报告工作流。

它已经是 Agent MVP 的可用底座，但还不是完整自主 Agent。

## 6. 当前最可能卡住的地方

### 6.1 数据源稳定性

Reddit、Amazon、媒体网页都依赖外部公开页面和工具链。可能卡在：

- 登录态失效；
- OpenCLI/Agent Reach 连接异常；
- 页面结构变化；
- 某些网页不可读；
- Amazon 公开数据不完整；
- 评论正文抓不到；
- 媒体文章被 paywall 截断。

### 6.2 搜索发现能力

媒体/榜单文章当前是 URL 驱动，还不是自动搜索发现。

后续如果要自动发现美国媒体测评、公开榜单和行业报告，需要接入：

- Exa；
- Google CSE；
- SerpAPI；
- 或其他可控搜索后端。

否则系统不能稳定声称“全网自动发现文章”。

### 6.3 竞品监控还没有状态闭环

目前竞品监控更像候选池展示，还没有完整监控闭环。

需要补：

- 竞品状态字段；
- 人工确认；
- watchlist；
- rejected/archive；
- 周期性重跑；
- 价格/评分/review/卖点变化对比；
- 变化摘要；
- 拆解优先级。

### 6.4 LLM 输出仍需证据约束

虽然现在已经做了证据链和上下文压缩，但仍需要继续加强：

- LLM 不得超出证据推断；
- 每条建议必须引用来源；
- 不同来源权重不同；
- 低质量来源不得支撑高置信结论；
- 明确区分事实、推断和建议。

## 7. 下一阶段建议

下一阶段可以围绕“从工作流变成轻量 Agent”推进。

优先级建议：

1. 建立统一 Source Card / Evidence Card 数据模型  
   把 Reddit、Amazon、媒体文章、竞品商品都变成统一证据对象，方便综合推理和引用。

2. 做数据充足性判断  
   让系统判断当前研究是否数据不足，并给出下一步补数建议。

3. 做 query 自动迭代  
   当结果太少或太泛时，自动尝试同义词、细分关键词和竞品品牌词。

4. 做竞品状态管理  
   把候选竞品变成 active/watchlist/rejected/archive，并允许人工反馈。

5. 做竞品监控变化摘要  
   对已确认竞品周期性重跑，比较价格、review 数、评分、卖点、badge 和媒体背书变化。

6. 做媒体/榜单自动发现  
   接搜索后端后，根据品类自动发现 Good Housekeeping、Wirecutter、Byrdie、Forbes、People、Health、Verywell Health、行业报告摘要等来源。

7. 做 Weekly Brief 输出  
   自动生成每周市场洞察快报、竞品候选清单、爆款深拆、基因库更新和产品机会池更新。

## 8. 阶段性结论

今天的进展已经把项目从单一 Reddit 市场洞察，推进到多数据源研发情报工作台。

上午完成的是 Reddit-first 洞察闭环。

下午新增的是：

- Amazon 商品信息采集；
- Reddit + Amazon 综合洞察；
- 媒体/榜单文章抓取；
- 来源权威审计；
- 竞品发现；
- 竞品监控入口；
- 历史研究体系。

当前 MVP 已经能回答：

- 美国文胸细分类目里用户在讨论什么；
- Amazon 货架上有哪些商品和价格/评分/review 信号；
- Reddit 与 Amazon 合在一起能支持哪些机会和风险判断；
- 哪些媒体/榜单文章可以作为外部背书或方向参考；
- 哪些商品值得进入竞品候选池；
- 过去的研究结果如何保存、回看和恢复。

下一步的关键不再是单纯增加页面，而是把这些数据源和分析结果组织成可迭代的 Agent 状态：知道缺什么、该补什么、哪些证据更可信、哪些竞品应该持续追踪，以及人工反馈如何改变下一轮优先级。
